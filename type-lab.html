Design System · Typography

데이터 서체 검토

관제 화면의 수치·코드·시각 표기에 모노스페이스가 필요한지 판단하기 위한 페이지입니다. 색상은 확정된 Dark 토큰(쿨강도 0.006 · Canvas 0.200)을 그대로 사용했습니다.

검토 서체 2번 섹션의 비교표를 제외한 페이지 전체에 적용됩니다.

1. 실시간 갱신에서 무슨 일이 일어나는가

아래 세 열은 같은 센서 값을 0.7초마다 갱신합니다. 왼쪽부터 SUIT 기본, SUIT + tabular-nums, 위에서 선택한 모노 서체입니다. 숫자 폭이 자릿수마다 다르면 값이 바뀔 때 열 전체가 좌우로 흔들립니다. 관제 화면처럼 하루 종일 갱신되는 화면에서는 이 미세한 떨림이 피로로 누적됩니다.

        브라우저에서는 되지만 Figma에서는 쓸 수 없습니다

        가운데 열은 안정적입니다 — SUIT 파일 자체에는 tabular figures 기능이 들어 있습니다. 그런데 Figma의 Type settings에 이 항목이 노출되지 않습니다. 디자이너가 Figma에서 켤 수 없고, Text Style에 담을 수도 없습니다.

        코드에서만 font-variant-numeric을 적용하면 Figma 화면과 실제 제품이 달라집니다. 시스템의 기여 원칙 “Figma Library를 유일한 운영 원본으로 삼는다”와 정면으로 어긋나므로 이 방법은 채택할 수 없습니다.

        따라서 정렬 문제는 해결되지 않은 상태로 남고, 모노 서체가 정렬과 인상 두 가지를 모두 담당해야 합니다. 적용 범위가 표의 수치까지 넓어집니다.

        3. 레퍼런스의 기술 라벨

        4. 제안하는 스타일

        Figma에서 tabular figures를 쓸 수 없으므로 수치 정렬까지 모노가 담당합니다. 기존 font-size·line-height 변수를 그대로 재사용하므로 새 Primitive는 필요 없습니다.

        적용 범위를 먼저 못박아야 합니다

        쓴다 — 표·리스트의 모든 수치, 로봇·설비 ID, way-point 코드, 미션 번호, 타임스탬프, 좌표, 펌웨어·빌드 버전, 로그 라인, 대문자 기술 라벨, KPI 대표 수치.

        쓰지 않는다 — 본문, 버튼 라벨, 메뉴, 제목, 알림 문구, 한글 문장. 모노는 읽는 속도가 느려 문장에 쓰면 손해입니다.

        표 안에서 한글 상태 라벨(완료·주의·위험)은 모노에 글자가 없어 자동으로 SUIT로 대체됩니다. 2번 섹션의 표가 실제로 그 상태이니, 두 서체가 한 행에 섞인 모습이 괜찮은지 확인해 주십시오. 이것이 이 방향의 유일한 시각적 부담입니다.

        5. 판단할 것

        서체 후보

        JetBrains Mono — 글자가 큼직하고 자간이 넓어 작은 크기에서 또렷합니다. 기술 라벨과 식별 코드처럼 짧고 독립된 문자열에 쓸 때 특히 깔끔합니다.

        IBM Plex Mono — 더 좁고 중성적입니다. 긴 표에 열을 많이 넣어야 할 때 유리합니다. 다만 표의 수치를 SUIT가 맡는다면 그 장점이 쓰일 자리가 줄어듭니다.

        용도를 라벨·코드·KPI로 좁히면 JetBrains Mono 쪽이 맞습니다. 둘 다 OFL 라이선스라 상업적 사용과 임베딩에 제약은 없습니다.

        비용

        서체 파일 1종 추가 · Text Style 4종 추가 · 수치를 표시하는 기존 컴포넌트의 Text Style 교체. 새 Primitive는 필요 없습니다.

        Foundation 변경이라 사용 우선순위 6단계 절차(해결 불가 이유 · 예상 재사용처 · Light/Dark 영향 · 네이밍 제시 후 승인)를 밟아야 합니다. Light/Dark 영향은 없습니다.

        해결 불가 이유는 이미 확보돼 있습니다 — SUIT의 tabular figures를 Figma에서 사용할 수 없다는 점, 그리고 관제 화면의 수치가 상시 갱신된다는 점입니다.
