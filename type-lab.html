Design System · Typography

데이터 서체 검토

관제 화면의 수치·코드·시각 표기에 모노스페이스가 필요한지 판단하기 위한 페이지입니다. 색상은 확정된 Dark 토큰(쿨강도 0.006 · Canvas 0.200)을 그대로 사용했습니다.

1. 실시간 갱신에서 무슨 일이 일어나는가

아래 세 열은 같은 센서 값을 0.7초마다 갱신합니다. 왼쪽부터 SUIT 기본, SUIT + tabular-nums, JetBrains Mono입니다. 숫자 폭이 자릿수마다 다르면 값이 바뀔 때 열 전체가 좌우로 흔들립니다. 관제 화면처럼 하루 종일 갱신되는 화면에서는 이 미세한 떨림이 피로로 누적됩니다.

        가운데 열을 먼저 보십시오

        tabular-nums는 서체를 바꾸지 않고 OpenType 기능만 켜는 방법입니다. 비용이 거의 없습니다. 가운데 열이 왼쪽과 똑같이 흔들린다면 SUIT가 이 기능을 지원하지 않는다는 뜻이고, 그때는 별도 서체가 유일한 해법이 됩니다.

        가운데 열이 오른쪽처럼 안정적이라면, 정렬 문제만 놓고 보면 서체를 추가할 이유가 없습니다. 그 경우 모노를 도입할 근거는 정렬이 아니라 레퍼런스의 계측기 인상이 됩니다.

        2. 실제 표에서 비교

        way-point 목록입니다. 코드·시각·수치가 세로로 정렬되는지, 한글과 섞였을 때 어색하지 않은지 보십시오.

        SUIT 기본
        JetBrains Mono
        IBM Plex Mono

        한글은 모노 서체에 글자가 없어 자동으로 SUIT로 대체됩니다. 즉 숫자·코드만 모노가 되고 한글은 그대로입니다. 폰트 스택을 "JetBrains Mono", "SUIT", sans-serif 순으로 두면 한 문장 안에서도 글자 단위로 나뉘어 적용됩니다.

        3. 레퍼런스의 기술 라벨

        Covalent가 쓰는 작은 대문자 모노 라벨입니다. 관제 제품에서는 장식이 아니라 화면·장비·좌표를 식별하는 실제 기능을 합니다.

        4. 제안하는 스타일

        기존 font-size·line-height 변수를 그대로 재사용하므로 새 Primitive는 필요 없습니다. Text Style 4종과 서체 파일만 추가됩니다.

        적용 범위를 먼저 못박아야 합니다

        쓴다 — 로봇·설비 ID, way-point 코드, 타임스탬프, 센서 수치, 좌표, 미션 번호, 펌웨어·빌드 버전, 로그 라인, 기술 라벨.

        쓰지 않는다 — 본문, 버튼 라벨, 메뉴, 제목, 알림 문구, 한글 문장. 모노는 가독 속도가 낮아 읽는 텍스트에 쓰면 손해입니다.

        이 경계가 없으면 “기술적으로 보이니까”라는 이유로 번져나가 화면이 오히려 어수선해집니다.

        5. 판단할 것

        서체 후보

        JetBrains Mono — 자간이 넓고 글자가 큼직해 작은 크기에서 잘 읽힙니다. 관제 화면에 유리합니다.

        IBM Plex Mono — 더 좁고 중성적입니다. 표 밀도를 높이기에 좋고 레퍼런스의 인상에 더 가깝습니다.

        둘 다 OFL 라이선스라 상업적 사용과 임베딩에 제약이 없습니다. 위 2번 표에서 나란히 비교하실 수 있습니다.

        비용

        서체 파일 1종 추가 · Text Style 4종 추가 · 기존 컴포넌트 중 수치를 표시하는 것들의 Text Style 교체.

        Foundation 변경이라 시스템의 사용 우선순위 6단계 절차(해결 불가 이유 · 예상 재사용처 · Light/Dark 영향 · 네이밍 제시 후 승인)를 밟아야 합니다. Light/Dark 영향은 없습니다 — 서체는 모드와 무관합니다.
