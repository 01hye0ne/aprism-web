스플래시 · 로그인

Figma UI_01/ CM-01 스플래시(630:3480) · UI_01/ CM-02 로그인 화면(630:3481) 를 옮긴 것입니다. 디자인 확정 전이라고 하셔서 구조만 그대로 두고 어긋난 값은 고쳤습니다. 아래가 고친 자리 전부입니다.

1. 로그인 패널 폭 — 791 이 아니라 800 입니다

Figma 는 Brand Panel 1120 + Login Panel 791 = 1911 이라 오른쪽 끝에 9 가 빕니다. 어느 쪽이 맞는 값인지는 안쪽 요소가 알려 줍니다.

요소패널 안 x800 기준 가운데791 기준 가운데
Login Form (400)200200 ✓195.5
Copyright (298)251251 ✓246.5

둘 다 800 기준으로 정확히 가운데입니다. 폼을 놓은 뒤 패널만 791 로 좁혀진 것으로 보고 패널을 800 으로 되돌렸습니다. 그러면 1120 + 800 = 1920 으로 딱 맞고, 폼과 저작권 줄의 가로 위치는 Figma 값 그대로가 됩니다.

구현에서는 로그인 면만 800 고정이고 브랜드 면이 나머지를 먹습니다 — 1920 이 아닌 폭에서도 폼의 여백이 흔들리지 않습니다.

2. 브랜드 덩어리가 왼쪽 면 가운데가 아니었습니다

로그인 화면의 락업+태그라인 덩어리(283 × 231)가 x = 507 에 있었습니다. 1120 면의 가운데는 418.5 라 88.5 오른쪽으로 밀려 있었습니다. 세로도 y = 355 로 가운데(396.5)보다 41.5 위였습니다. 가로·세로 모두 가운데로 옮겼습니다.

3. 로고는 가운데인데 글자는 왼쪽이었습니다

로그인 화면의 Tagline 은 counterAxisAlignItems = MIN 이라 두 줄이 왼쪽에 붙습니다. 그런데 그 위 로고는 가운데라, 짧은 국문 줄(222)이 긴 영문 줄(283) 안에서 왼쪽으로 쏠려 보였습니다. 스플래시와 같이 가운데 정렬로 맞췄습니다(스플래시 쪽은 CENTER 입니다).

4. 폼이 위로 붙어 아래가 351 비어 있었습니다

Figma 는 Login Form 이 y = 222 에서 시작해 673 에서 끝나고, 저작권 줄이 944 에 따로 놓여 있습니다. 그 사이 351 이 그냥 빕니다.

구현은 저작권 줄을 뺀 나머지 자리의 한가운데에 폼을 세웁니다 (열 방향 flex 에 margin: auto 0). 위아래 여백 64 를 주면 저작권 줄이 y = 942 에 서는데 Figma 의 944 와 2 차이입니다 — 저작권 줄은 사실상 그대로고 폼만 56 내려온 셈입니다.

5. 체크박스 — 컴포넌트에서 둘을 고쳤습니다

Figma Checkbox여기
상자 자리라벨 오른쪽(자식 순서가 Label → Box)왼쪽
아래 테두리border/default 1px — Default 세 변형에만 있고 Disabled 두 변형에는 없습니다없음

아래 테두리는 변형끼리 어긋나 있어 남은 자국으로 봤습니다. 나머지(상자 18 · radius 4 · 패딩 8/8/8/12 · gap 8 · 줄 높이 38 · On 일 때 bg/brand 면 + 14 짜리 check)는 Figma 그대로입니다.

Figma 컴포넌트는 손대지 않았습니다. 다른 화면에서도 쓰는 컴포넌트라 말씀 주시면 그때 고치겠습니다.

6. 입력칸 안내 문구를 placeholder 로 내렸습니다

Figma 는 Text Field 의 Value 자리에 "사번 또는 아이디를 입력하세요" 를 fg/primary 로 적어 두었습니다. 실제로는 친 글자가 아니라 안내 문구라서 fg/tertiary 로 낮췄습니다. 친 글자가 fg/primary 입니다.

7. 눈 아이콘을 실제 토글로 만들었습니다

Figma 에는 Icon / eye-off 만 놓여 있고 상태가 없습니다. 누르면 Icon / eye 로 바뀌며 비밀번호가 보입니다 (aria-pressed 로 상태를 알립니다). 두 아이콘 모두 Figma 의 01.7 Icon 페이지에서 내려받아 assets/icons/ 에 넣었습니다.

8. 그대로 둔 것

  • 로그인 버튼이 Secondary 입니다 — 화면의 주 동작인데 보조 버튼입니다. 정렬 문제가 아니라 고르신 값이라 그린 대로 뒀습니다. Primary 로 바꿀지는 말씀해 주세요.
  • Options 줄의 오른쪽이 비어 있습니다. SPACE_BETWEEN 인데 자식이 체크박스 하나뿐입니다. "비밀번호 찾기" 같은 링크 자리로 보고 줄은 그대로 두었습니다.
  • 태그라인 아랫줄이 두 화면에서 다릅니다. 스플래시는 Label/1(14/20 ExtraBold) 대문자, 로그인은 Body/4(13/20 Regular) 원래 대소문자입니다. 크기 차이는 의도로 보고 뒀습니다.
  • 락업 흰색. Figma 가 변수 없이 #FFFFFF 로 박아 둔 값이라 여기서도 흰색 그대로입니다. Light 로 뒤집을 때만 fg/primary 로 넘어갑니다.

9. 타입 램프 이름을 Figma 에 다시 맞췄습니다

Body 램프에 Body/4 가 끼면서 번호가 한 칸씩 밀려 있었습니다. app-shell.css 의 .t-* 는 예전 이름이라 .t-body-2 가 14/22 를 가리키고 있었습니다.

클래스전후 (Figma 현재)
.t-body-1없음20/32 SemiBold
.t-body-214/2216/24
.t-body-313/2014/22
.t-body-4없음13/20
.t-heading-2없음24/32 SemiBold, -1%

쓰이던 곳은 세 화면의 사이트 셀렉트 하나뿐이라 t-body-3 → t-body-4 로 바꿨습니다 — 그려지는 크기는 그대로고 이름만 맞았습니다.

Typography/Label/1/SemiBold 는 실제 굵기가 ExtraBold(800) 입니다. 이름과 값이 어긋난 스타일이 넷(Heading/3 · Label/1 · Title/1,2 · Body/1)인데 여기서는 값을 따릅니다 — 전부터 그렇게 두고 있던 규칙입니다.

11. 화면 밖 동작

  • 스플래시 → 로그인 — 2 초 머문 뒤 넘어갑니다. 누르거나 키를 치면 바로 넘어가고, ?hold=0 으로 열면 멈춰 있습니다(캡처용).
  • 로그인 → 미션 설정 — 붙일 인증이 없어서 값을 확인하지 않고 mission-setup.html 로 넘깁니다. 들어오면 바로 미션을 짜는 흐름이라 관제 메인이 아니라 미션 설정이 다음 화면입니다. 서버가 붙으면 그 자리가 요청으로 바뀝니다.
  • 1080 아래 — 브랜드 면을 접고 로그인 면만 남깁니다. 관제실 기준이 1920 이라 별도 화면을 그리는 대신 무너지지만 않게 했습니다.

12. 비밀번호 변경 강제 화면 (677:7468)

비밀번호 사용 기간이 만료된 계정이 보는 화면입니다. 브랜드 면 · 카드 · 입력칸 · Help 는 로그인과 같은 부품이라 새로 만든 것은 넷입니다 — 경고 알림, 규칙 네 줄, Danger 버튼, 카드 밑 링크.

12-1. 카드가 오른쪽 칸의 가운데에 섭니다

로그인 카드는 브랜드 면 끝에서 9 만 띄우고 왼쪽에 붙는데, 이 화면은 다릅니다. 오른쪽 칸 1129..1921(792) 안에서 카드가 1291..1759(468) 라 양옆이 162 로 같습니다. 가운데 정렬로 두고, 왼쪽 9 는 그대로 둔 채 오른쪽 패딩을 0 으로 잡아 1290.5 에 세웠습니다(Figma 1291).

12-2. 알림은 Header 안입니다 — 블록이 아닙니다

Inline Notice 가 카드의 독립 블록처럼 보이지만 Header(677:7067)의 세 번째 자식입니다. 그래서 부제와의 간격이 블록 간격 40 이 아니라 8 입니다 (제목 y0 → 부제 y48 → 알림 y78, 둘 다 8).

12-3. 규칙 네 줄은 상태를 가집니다

Figma 스냅숏은 첫 줄만 초록(status/normal/fg)이고 나머지 셋은 회색(fg/disabled)입니다. 글자는 넷 다 fg/secondary 로 같습니다. 체크 아이콘 색으로 채워진 줄과 아닌 줄을 가르는 화면이라는 뜻이라, 친 값에 따라 네 줄을 실시간으로 켜고 끕니다. 비어 있는 첫 화면에서는 넷 다 회색입니다 — Figma 스냅숏은 4자 이상을 이미 친 상태를 그린 것입니다.

규칙여기서 보는 것
4자 이상길이
영문 · 숫자 · 특수문자 중 2종 이상세 갈래 중 섞인 갈래 수
아이디와 3자 이상 연속 일치 금지로그인에서 친 아이디의 3글자 창을 훑습니다
최근 비밀번호와 중복 금지위 칸의 현재 비밀번호와 같은지

셋째 줄은 이 화면에 아이디 칸이 없어서 볼 값이 없습니다. 그래서 로그인에서 넘어올 때 친 아이디만 sessionStorage 에 남깁니다(비밀번호는 남기지 않습니다). 바로 이 주소로 들어와 아이디를 모르면 어길 것이 없어 통과로 봅니다.

넷째 줄의 "최근"은 이 화면이 아는 범위가 현재 비밀번호 한 칸뿐입니다. 그 이전 이력은 서버가 볼 자리입니다.

12-4. 버튼은 Danger 이고, Figma 는 Disabled 상태로 그려져 있습니다

Type=Danger, Size=Large, State=Disabled 입니다. 규칙을 채우기 전 상태를 그려 둔 것으로 보고, 네 줄이 다 켜지고 새 비밀번호 두 번이 같을 때 열리게 했습니다. 열린 모습은 같은 컴포넌트의 State=Default(button/danger/bg/default)입니다. hover 는 Figma 에 변형이 없어 다른 버튼들과 맞춰 더했습니다 (button/danger/bg/hover 는 이미 토큰에 있습니다).

12-5. "다른 계정으로 로그인" 은 카드 밖입니다

이름이 Copyright 인데 내용은 링크이고, 로그인의 저작권 줄과 달리 카드 안이 아니라 카드 밖입니다 — 카드 하단 904.5 에서 20 아래인 924.5 에, 카드 폭 기준 가운데로 놓여 있습니다. 색도 fg/brand 라 링크로 보고 login.html 로 걸었습니다.

12-6. 현재 비밀번호 칸의 점 여덟 개는 placeholder 로 내렸습니다

Figma 는 Value 자리에 •••••••• 를 fg/primary 로 적어 두었습니다. 나머지 두 칸이 안내 문구인 것과 같은 자리라 친 값이 아니라 목업으로 보고, 위 6번과 같은 규칙으로 "현재 비밀번호를 입력하세요" placeholder 로 바꿨습니다.

12-7. 같이 고친 것

  • 눈 아이콘이 한 칸에서만 먹었습니다. auth.js 가 querySelector 로 첫 하나만 잡고 있었습니다. 이 화면은 칸이 셋이라 querySelectorAll 로 바꿨습니다 — 로그인 쪽 동작은 그대로입니다.
  • 카드가 창보다 커질 수 있습니다. 로그인 카드는 613 인데 이 카드는 825 입니다. .auth 가 overflow:hidden 이라 낮은 화면에서 잘리므로, 카드가 앉는 칸만 세로로 스크롤되게 했습니다.

12-9. 두 번 친 값이 다를 때 — Text Field 의 State=Error (49:138)

Text Field 컴포넌트에 State 가 다섯입니다 (Default · Hover · Focus · Error · Disabled). 어긋난 칸에 Error 를 그대로 얹었습니다. Default 와 다른 것은 셋뿐입니다.

DefaultError
칸 테두리border/default 1px status/critical/border 2px
칸 끝없음 20 짜리 Icon / warning(status/critical/icon)
Helperfg/tertiary 12/18 status/critical/fg 12/18

칸 높이는 36 그대로입니다 — 테두리가 굵어져도 box-sizing: border-box 라 안 밀립니다. 경고 아이콘은 Figma 가 Trailing Icon 다음 자리에 따로 두는데, 이 화면의 그 자리에는 눈 아이콘이 있어서 눈 아이콘 오른쪽에 붙습니다.

Helper 줄은 이 화면에서 처음 씁니다. 다른 화면의 Text Field 는 Helper 를 안 써서 app-shell.css 에 규칙이 없었습니다. 안내문으로 늘 띄우지 않고 어긋났을 때만 보이게 했습니다 — 그래서 그때 칸이 26(18 + gap 8) 만큼 자랍니다.

치는 도중에는 말하지 않습니다. 확인 칸을 한 번 떠난 뒤부터 어긋난 것을 알리고, 그다음부터는 고치는 대로 실시간으로 따라가 맞는 순간 사라집니다. 첫 글자부터 빨개지는 것을 피하려는 것입니다.

문구는 Figma 에 없어서 여기서 썼습니다 — "새 비밀번호와 일치하지 않습니다." Helper 의 기본값은 컴포넌트 예시문(터빈 단위로…)이라 그대로 쓸 수 없었습니다.

Focus 와 겹쳤을 때의 그림은 Figma 에 없습니다 — 둘이 다른 변형입니다. 틀렸다는 사실이 먼저라 색은 Error 쪽을 두고, 포커스 테두리만 같은 빨강으로 얹어 어디에 있는지는 잃지 않게 했습니다.

읽어 주는 쪽으로는 aria-invalid 와 aria-describedby 를 걸고 메시지 줄에 role="alert" 를 뒀습니다.

12-8. 흐름

붙일 서버가 없어서 값을 보내지 않고 mission-setup.html 로 넘깁니다 — 로그인과 같은 자리입니다. 로그인에서 이 화면으로 보내는 분기는 넣지 않았습니다 — 지금 로그인은 여전히 바로 미션 설정으로 갑니다. 만료 계정을 여기로 보내는 조건은 서버가 정할 자리라 말씀 주시면 그때 잇겠습니다.
