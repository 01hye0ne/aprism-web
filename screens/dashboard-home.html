Publishing Notes

이 화면을 옮기며 판단한 것

Figma UI_99_작업화면 · Template / 04.1 Dashboard Home(node 121:7848)을 옮겼습니다. GUI 작업 전이라 색과 서체는 그대로 두고, 구조만 손봤습니다.

1. 무엇이 늘어나는가를 코드에서 정했습니다

Figma 파일은 1920×1024 한 점에서만 성립합니다. Two Column까지는 FILL이 잘 내려오는데 그 안의 두 자식이 모두 FIXED라, 지도 폭 1170이 "나머지"가 아니라 "상수"로 굳어 있습니다.

다만 Map Panel 컴포넌트 설명에는 이미 답이 적혀 있습니다 — "Canvas는 Fill로 늘어난다. 1600px 이상에서 지도는 제한 없이 확장한다." 설명을 따랐습니다. 폭이 고정된 것은 GNB · Context Panel(240) · Right Panel(360) 셋뿐이고, 나머지는 지도가 흡수합니다. 창 크기를 바꿔보시면 확인됩니다.

2. 우측 패널이 높이를 채우고, 타임라인만 스크롤합니다

Figma에서 이 패널은 세로 HUG라 912 트랙 안에서 839에서 멈춥니다(73px 빈 공간). 웨이포인트가 늘면 Content의 clipsContent에 잘려 아무 경고 없이 사라지고, 바닥의 「수동 조작 / 미션 관리」도 같이 밀려 내려갑니다.

여기서는 패널이 높이를 채우고, 길이가 변하는 타임라인만 스크롤 영역으로 두었습니다. 버튼은 항상 바닥에 남습니다.

3. AI 블록을 지도 안으로 옮겼습니다

Figma에서 이 블록은 Status Bar와 형제인 절대배치 노드라 지도와 아무 관계가 없고, 제약이 MIN/MIN이라 폭이 변해도 좌상단에 붙박이입니다. 좌표를 재보면 지도 왼쪽 경계보다 4px 밖으로 나가 있습니다(13431 vs 13435).

Map Panel의 자식으로 옮겨서 지도를 따라가게 했습니다. 4px 어긋남도 같이 해소됩니다. 이 영역은 Figma에서 다시 디자인하실 예정이라 나머지는 그대로 두었습니다.

4. 로봇 카드는 대수 상한 없이 버팁니다

최대 대수가 아직 정해지지 않아서, 몇 대가 되든 깨지지 않는 쪽으로 두었습니다. 카드는 폭을 나눠 갖되 92px 아래로는 줄지 않고, 그보다 좁아지면 가로로 스크롤합니다. 3대일 때는 Figma와 같은 폭이 나옵니다.

Figma의 현재 구조는 NO_WRAP + 3장 균등이라 4대가 되면 카드당 74px이 되어 「수행 중」 「64%」 「Strong」이 들어갈 자리가 없습니다. 상한이 정해지면 다시 조정하겠습니다.

5. 면 위계를 시스템 규칙대로 되돌렸습니다

Figma에서 Main과 Map Panel의 배경이 모두 button/primary/bg/disabled로 칠해져 있습니다 — 비활성 버튼 색을 페이지 배경으로 쓰고 있습니다. 그 결과 캔버스가 가장 어둡고 패널·카드가 밝아야 한다는 규칙이 이 화면에서는 보이지 않습니다.

Main은 bg/canvas, Map Panel은 bg/surface/default로 두었습니다. 이번 톤 작업에서 확정한 위계가 실제 화면에서 어떻게 보이는지 확인하실 수 있습니다. 되돌리길 원하시면 알려주세요.

7. 확인이 필요한 지점

  • Status Bar가 컴포넌트 마스터입니다. 화면 템플릿 안에 원본이 들어앉아 있고, 파일 전체에 인스턴스가 0개입니다. 게다가 Auto Layout이 없어 우측 묶음이 왼쪽에 못 박혀 있습니다. 여기서는 GNB Rail과 같은 방식으로 다시 짰습니다.
  • Mission Timeline Iist — List의 l이 대문자 I입니다. published 라이브러리 컴포넌트라 이 오타가 이 파일을 쓰는 모든 화면에 퍼집니다.
  • Progress Bar에 그라데이션이 들어가 있습니다. 컴포넌트 설명에 "Gradient를 Fill에 쓰지 않는다"고 적혀 있는데, 실제 Fill은 #285896 → #6f99f5 → #ffdadb 하드코딩입니다. 끝의 분홍이 어느 토큰에도 없습니다. 일단 그대로 옮겼습니다.
  • GNB 항목 8개가 모두 fg/disabled입니다. 선택된 「관제」만 fg/brand입니다. 다른 영역이 아직 안 만들어져서 의도적으로 비활성 처리하신 것인지 확인 부탁드립니다.
  • 로봇 카드에 배터리 수치가 두 개입니다. 막대 옆 64%와 번개 아이콘 옆 78%가 서로 다른 값을 가리킵니다. Battery 행과 Battery Gauge 인스턴스가 겹쳐 들어간 것으로 보입니다.
  • 껍데기 프레임 3개 — Frame 1597881552(완전 통과용), Main/Content(중복), Frame 1597881537(부모와 gap 중복). 웹에서는 걷어냈고 Figma에서는 그대로 두었습니다.

8. 아이콘과 서체

내보낸 SVG 27개에는 Light 모드 색이 구워져 있어 그대로 쓰면 테마를 따라가지 못합니다. CSS mask로 모양만 쓰고 색은 토큰이 채우도록 했습니다. 우측 아래에서 테마를 바꿔보시면 확인됩니다.

수치에는 SUIT의 tabular-nums를 적용해 자릿수를 고정했습니다. Figma의 Type 패널에는 이 항목이 없어서 Figma에서는 확인되지 않지만, 브라우저에서는 동작합니다. 지난번에 만든 Typography/Mono/* 스타일은 아직 이 화면에 적용되지 않은 상태라 그대로 두었습니다.

9. tokens.css를 다시 만들었습니다

이 화면을 옮기며 대조해 보니 tokens.css의 Semantic 매핑에 Light 3곳 · Dark 7곳이 실제 Figma 값과 달랐습니다 (chart/track, chart/grid, bg/interactive/hover, status/normal/icon 등). 변수 설명을 근거로 삼았던 부분이 원인입니다.

valuesByMode 실측 덤프로 전부 다시 생성했습니다. Primitive 106 · Semantic 90×2 · Component 42, 합계 244개 변수입니다. 이제 Component 계층까지 들어와서 button/*, input/*, navigation/*을 화면에서 그대로 쓸 수 있습니다.
