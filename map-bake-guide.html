왜 굽나

레퍼런스의 무게감은 대부분 AO에서 나와요. 건물은 움직이지 않으니 한 번 구워 두면 실행 비용 없이 늘 그 품질이에요.

실시간 AO (1단계 GTAO)구운 AO (2단계)
품질화면 공간 계산이라 얕고, 화면 가장자리에서 끊겨요광선 추적이라 깊고 부드러워요 (레퍼런스 ③ 수준)
속도프레임마다 계산 — 4K · 저사양 PC에서 부담텍스처 한 장 읽기 — 거의 0
비치는 벽Focus Point로 벽이 비칠 때 판단이 흔들려요벽과 함께 옅어져 자연스러워요
경로 선벽 가까이 지나는 경로 선까지 어두워져요건물 면에만 붙어 경로 색이 그대로예요
테마둘 다 "어둡게 곱하기"라 다크 · 라이트, 덩이 색을 바꿔도 그대로 맞아요

AO만 구워요. 빛과 색까지 굽는 라이트맵은 레퍼런스 ③에 더 가깝지만, 색이 텍스처에 박혀서 테마 전환 · 선택 강조 · Focus Point 투명도와 부딪혀요.

0. 준비

10분

  • Blender 4.2 LTS 이상 (무료, blender.org). 메뉴 이름은 4.2 영문 기준이에요.
  • GPU가 있으면 Edit › Preferences › System › Cycles Render Devices에서 CUDA · OptiX(엔비디아)나 HIP(AMD)를 켜 주세요. 굽는 시간이 몇 분에서 수십 초로 줄어요.
  • 원본 파일: aprism-web/assets/model/apro-b3-b4.glb — 지금 지도가 쓰는 모델이에요. 라이노에서 새로 내보내도 되지만, 이 파일에서 시작하면 이름 · 위치가 지금과 똑같아서 코드가 그대로 읽어요.

1. 불러오기

  1. 새 파일을 열고 기본 큐브 · 카메라 · 라이트를 지워요 (A → X).
  2. File › Import › glTF 2.0 → apro-b3-b4.glb.
  3. Outliner에서 구조를 확인해요. 맨 위가 층(지하 4층 · 지하 3층), 그 안이 레이어(floor · wall · equipment · stairs)예요. 코드가 이 이름으로 층과 색을 정하니 이름 · 묶음 · 위치 · 크기는 절대 바꾸지 않아요.
  4. 선(Curve)으로 들어온 것이 있으면 그대로 두세요. 코드가 알아서 빼요.

2. AO 전용 UV 펴기

모든 덩이가 텍스처 한 장(아틀라스)을 나눠 쓰게 펼쳐요.

  1. Outliner에서 메시만 전부 고르고 (Select › Select All by Type › Mesh), 3D 뷰에서 Tab으로 편집 모드에 들어가요. 여러 덩이를 한꺼번에 편집하는 상태예요.
  2. A로 면을 전부 고르고 UV › Lightmap Pack을 실행해요.
    • Selection: All Faces
    • Share Texture Space: 켬 ← 한 장에 다 모으는 옵션이에요
    • Pack Quality: 48 · Margin: 0.2 안팎
    모서리가 많은 건물은 Lightmap Pack이 잘 맞아요. 결과가 지저분하면 UV › Smart UV Project(Island Margin 0.005)를 쓴 뒤 UV › Pack Islands로 다시 모아도 돼요.
  3. Tab으로 나와요. UV Editing 탭에서 섬들이 0~1 칸 안에 겹치지 않고 펼쳐졌는지 봐요.

바닥판처럼 아주 큰 면은 칸을 많이 차지해야 그늘이 뭉개지지 않아요. 바닥이 너무 작게 잡혔으면 바닥 섬만 골라 키운(S) 뒤 Pack Islands를 다시 돌려요.

3. Cycles로 AO 굽기

3-1. 담을 이미지 만들기

  1. Image Editor에서 Image › New → 이름 apro-ao, 4096 × 4096, Color 흰색, Alpha 끔, 32-bit Float 켬 (굽는 동안 계조가 깨지지 않게).
  2. 각 재질에 이 이미지를 걸어요. Shader Editor에서 재질마다 Add › Texture › Image Texture → apro-ao를 고르고, 그 노드를 클릭해 활성(흰 테)으로 둬요. 아무 데도 연결하지 않아요 — 굽는 대상이라는 표시일 뿐이에요.
    • 재질이 여러 개면 전부 해야 해요. 하나라도 빠지면 그 덩이는 안 구워지고 오류가 나요.

3-2. 굽기 설정

위치값이유
Render › Render EngineCycles · Device GPU굽기는 Cycles만 돼요
Render › Sampling › RenderMax Samples 256 · Denoise 켬128이면 거칠고 512는 차이가 거의 없어요
World › Settings › Ambient Occlusion › Distance층 높이의 ⅓ 쯤 (모델 단위로 1.0~1.5 부근부터)너무 크면 위층 바닥판이 아래층 전체를 덮어 다 까매져요
Render › Bake › Bake TypeAmbient Occlusion
Bake › Output › Margin16 px · Extend섬 경계의 검은 줄(이음매)을 막아요
Bake › Selected to Active끔

3-3. 굽기

  1. Object 모드에서 메시를 전부 고르고 Render › Bake › Bake.
  2. 위층 바닥판이 아래층을 덮는 문제: Distance를 낮춰도 아래층이 전반적으로 어두우면, 층을 하나씩 구워요 — 지하 3층을 숨기고(눈 아이콘이 아니라 Disable in Renders 카메라 아이콘) 지하 4층만 고르고 굽기 → 반대로 한 번 더. 같은 이미지에 이어서 구워져요.
  3. Image Editor에서 결과를 봐요. 벽 밑동 · 설비 아래 · 구석이 부드럽게 어둡고 나머지는 흰색이면 정상이에요.
  4. Image › Save As → PNG · BW · 8-bit, 이름 apro-b3-b4-ao.png.

4. 내보내기

  1. File › Export › glTF 2.0 → Format glTF Binary (.glb), 이름 apro-b3-b4-ao.glb.
  2. Include: Selected Objects 끔 (전부 내보내기). Data › Mesh: UVs 켬 · Normals 켬. Material: No export 또는 Placeholder — 재질은 코드가 입혀요.
  3. Compression(Draco)은 끔. 지금 코드가 Draco를 풀지 않아요.
  4. Transform › +Y Up 켬(기본값). 바꾸면 지도가 누워요.

AO는 GLB에 넣지 않고 PNG를 따로 넘겨요. glTF Occlusion 소켓 연결이 번거롭고, 따로 두면 PNG만 다시 구워 바꿔 끼우기 쉬워요.

5. 넘기기

  • 두 파일을 aprism-web/assets/ 바로 아래에 넣고 알려 주세요: apro-b3-b4-ao.glb · apro-b3-b4-ao.png. 하위 폴더 정리와 연결은 제가 해요.
  • 제가 할 일
    • 지도 코드가 지금 UV를 지우는데(재질에 텍스처가 없어서), AO를 붙이려고 UV를 남기게 바꿔요.
    • PNG를 aoMap으로 붙이고, 세기를 다크 · 라이트 따로 맞출 수 있게 렌더 실험 조절판에 넣어요.
    • 1단계 GTAO와 나란히 비교한 뒤 하나로 정해요. 구운 AO가 낫다면 GTAO는 빼서 부하를 줄여요.
    • PNG는 화질을 보고 2048 · WebP로 줄여요 (base64로 들고 있어 용량이 ⅓ 더 늘어나요). 지금 모델이 4MB예요.

점검

  • ☐ Outliner의 층 · 레이어 이름이 원본과 같다 (지하 4층 › floor · wall · equipment · stairs)
  • ☐ UV 섬이 0~1 칸 안에 있고 서로 겹치지 않는다
  • ☐ AO 이미지에 섬 경계를 따라 검은 줄이 없다
  • ☐ 아래층이 통째로 어둡지 않다 (위층 바닥판 문제)
  • ☐ GLB를 다시 불러왔을 때 위치 · 크기 · 방향이 원본과 같다

문제 해결

증상원인 · 해결
"No active image found"그 덩이의 재질에 apro-ao 이미지 노드가 없거나 활성이 아니에요. 3-1의 2번을 그 재질에 다시 해요.
얼룩덜룩 · 자글자글Samples를 올리거나 Denoise를 켜요. 그래도 남으면 이미지를 4096으로, 섬을 키워요.
전체가 회색 · 검정AO Distance가 너무 커요. 아니면 면 방향(노멀)이 뒤집혔어요 — 편집 모드에서 Mesh › Normals › Recalculate Outside.
섬 경계에 검은 선Margin을 24 px로 올려요. UV 섬 간격(Margin)도 넓혀요.
굽기가 너무 오래 걸림GPU가 켜졌는지 보세요. 시험은 1024 · 64 Samples로 먼저 돌리고, 마지막에만 4096 · 256으로.
계단실 구멍 둘레가 어색함위층 바닥의 계단 구멍은 코드가 셰이더로 뚫어요. 모델에는 구멍이 없어서, 구멍 자리에도 그늘이 생겨요. 보이면 알려 주세요 — 그 자리만 코드에서 걷을게요.
