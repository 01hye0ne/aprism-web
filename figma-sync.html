Design System · Change Set

Figma 반영 목록

톤 실험실에서 확정한 값을 UI_00_Design System 에 옮기기 위한 변경 목록입니다. Primitive 값 교체가 대부분이고 Semantic 바인딩 변경은 두 건입니다.

변경 로그

시스템 기여 원칙이 요구하는 항목입니다 — 변경 이유, 영향 범위, Migration 필요 여부.

변경 이유
Gray 램프 안에 쿨 뉴트럴과 순수 무채색이 섞여 Light·Dark 가 다른 제품처럼 보였습니다. Dark 층위 간격이 1.09:1 이하라 카드와 배경이 구분되지 않았고, bg/canvas 바인딩이 문서와 반대 방향이었습니다. 브랜드 색은 임시값 상태였고, Gradient/Main 은 어느 텍스트 색으로도 전 구간을 읽을 수 없었습니다.
영향 범위
Primitive 28개 값 교체 · Semantic 바인딩 2건 · Gradient Paint Style 4종 · Text Style 4종 신규. Semantic 이름과 구조는 그대로이므로 Component API 변경은 없습니다. 모든 화면의 배경·카드·텍스트·상태색이 함께 바뀝니다.
Migration
Primitive 값만 바꾸면 Semantic 이 alias 로 전파되므로 기존 인스턴스는 자동 반영됩니다. 수동 작업이 필요한 것은 Gradient Paint Style 의 stop 재정의와, 수치를 표시하는 컴포넌트의 Text Style 을 Mono 계열로 교체하는 작업입니다.
검증
주요 전경 × 배경 17개 조합이 모두 WCAG 기준을 통과합니다. 기존에도 미달이던 Light fg/tertiary(3.55:1) 한 건만 남아 있으며 이번 변경으로 생긴 것이 아닙니다.

3. Semantic 바인딩 변경

이 두 건 외에 Semantic 은 손대지 않습니다.

토큰모드현재변경
bg/canvasDarkcolor/gray/750→color/gray/950
border/brandLight설명은 main/700→실측대로 main/500 로 설명 수정

bg/canvas 는 Dark 에서 가장 밝은 면이었습니다. 배경이 카드보다 밝아 층위가 뒤집혀 있었고 설계 문서의 “Card 는 Canvas 보다 한 단계 밝은 Surface” 규칙과도 반대였습니다. 가장 어두운 gray/950 으로 되돌립니다.

border/brand 는 값 변경이 아니라 설명 정정입니다. 실제 바인딩은 main/500 인데 설명에 main/700 이라고 적혀 있습니다.

4. Gradient Paint Style

4종 모두 stop 을 다시 정의합니다. 배경색을 stop 에 넣지 않고 같은 색의 불투명도만 0 까지 낮춰 배경에 녹입니다. Paint Style 은 모드를 갖지 않으므로 이 방식만 Light·Dark 양쪽에서 성립합니다.

주의
끝 stop 을 transparent 키워드로 두면 검정 투명으로 보간돼 중간 구간이 탁해집니다. Figma 에서도 같은 색을 복제해 불투명도만 0 으로 내리십시오.

코어가 원색이라 그 위에는 본문을 얹을 수 없습니다. 텍스트 안전 구간은 Dark 기준 danger 2% · main 4% · safe 5% · warning 10% 이후입니다.

5. Text Style 신규

Figma 에서 SUIT 의 tabular figures 를 쓸 수 없어 수치 정렬을 모노가 담당합니다. 기존 font-size · line-height 변수를 재사용하므로 새 Primitive 는 없습니다. 서체는 JetBrains Mono(OFL)입니다.

스타일크기 / 행간용도
Typography/Mono/Metric20 / 28 MediumKPI 대표 수치, 게이지 값
Typography/Mono/Data/114 / 20 Medium표 셀 수치, 좌표, 리스트 값
Typography/Mono/Data/213 / 18 Regular밀도 높은 표, 로그 라인
Typography/Mono/Label12 / 18 Medium · 대문자 · 자간 0.09em기술 라벨, 섹션 식별자

적용하지 않는 곳 — 본문, 버튼 라벨, 메뉴, 제목, 알림 문구, 한글 문장. 한글은 모노에 글자가 없어 SUIT 로 자동 대체되므로, 표에서는 수치가 모노, 상태 라벨이 SUIT 로 나뉩니다.

6. 작업 순서

시스템 기여 원칙의 “Foundation → Semantic → Component → Pattern → Screen 영향 순서” 를 따릅니다.

  1. Primitive 값 교체 — Neutral 15개, 색상 계열 13개. 이 시점에 모든 화면이 한 번에 바뀝니다.
  2. gradient-end 2개 삭제 — 새 그라데이션에서 참조하지 않습니다.
  3. Semantic 바인딩 2건 — bg/canvas Dark, border/brand 설명.
  4. Gradient Paint Style 4종 재정의 — 위 stop 표대로.
  5. Text Style 4종 추가 — 서체 설치 후.
  6. 수치 컴포넌트의 Text Style 교체 — 표·KPI·로그.
  7. Dark 화면 육안 검증 — 층위 구분, 상태색 식별, Alert 가시성.

아직 확인하지 못한 것

Semantic 90개 중 화면과 검색으로 확인한 것은 일부입니다. 나머지와 Component 컬렉션 42개, 그리고 bg/overlay 가 참조하는 alpha/scrim/* 의 실제 알파값은 아직 실측하지 못했습니다. Foundations 페이지에 토큰 전량을 바인딩한 프레임이 생기면 get_variable_defs 로 한 번에 대조할 수 있습니다.

danger/400 추가 건은 보류 중입니다 — Dark Danger 버튼이 hover 에서 어두워지는 문제를 해결하려면 필요하지만, 그 버튼의 라벨 색이 흰색인지 어두운 색인지 확인이 필요합니다.
